# Разбор PDF-каталога

Скрипты готовят фрагменты `server/src/db/catalog/catalog.json` из каталога АТЛАНТА-26.
Сам PDF в репозиторий не кладётся — он нужен только на время разбора.

```bash
pip install --break-system-packages pypdf pymupdf
python3 scripts/catalog/build_marker.py "/путь/Каталог АТЛАНТА-26.pdf" /tmp/out
```

На выходе `/tmp/out/<раздел>.json` и `/tmp/out/files/*` — фрагмент и фото.
Дальше фрагмент просматривается глазами (названия, привязка фото, коды) и
вливается в `catalog.json`; импорт в базу — `npm run db:catalog`.

| Скрипт | Раздел | Стр. |
|---|---|---|
| `build_marker.py` | Фонари габаритные (бортовые огни) | 19–46 |
| `build_lights.py` | Поворот, ФОНЗ, ЗХ, ПТФ, ДСТ, плафоны | 48, 50–66 |
| `build_harness.py` | Электропровода (жгуты) | 68–73 |
| `build_extras.py` | Соединители и прочие устройства | 74–79 |

Особенности каталога, которые уже учтены:

- код модификации обычно в скобках после артикула, но бывает и в середине —
  `А.3731.010 (03.04)-Т`, `А.3731.018-41 (03)-У`;
- описания в таблицах переносятся на 2–4 строки, строки «артикул + код»
  и «описание» разделены;
- у части семейств страница с фото и характеристиками отделена от страницы
  с таблицей артикулов (стр. 26/27, 41/42, 43/44);
- фото привязывается по индексу только когда число фото совпадает с числом
  артикулов на странице, иначе одно фото отдаётся всему семейству с пометкой
  в описании;
- в разделе ФОНЗ фото стоит **ниже** таблицы, поэтому выбирается по минимальной
  `y0` (фото всегда выше чертежа), с отбраковкой `w < 300`, `h >= 1100`,
  `w/h <= 0.5` — так отсекаются логотипы сертификатов;
- в разделе жгутов на странице несколько подтаблиц: заголовок «А.3724.* ЖГУТ …»
  и пометка «(РОЗЕТКА-ВИЛКА)» — отдельные блоки, пометка своя у каждой
  подтаблицы; артикул сразу полный, модификаций нет;
- в жгутах описание и фото стоят в блоке **выше** артикула, причём на разную
  высоту, поэтому они привязываются к ближайшему артикулу по центру блока
  (±70 pt), а не «следующему по порядку»;
- на стр. 70–72 каталога колонка «ФОТО» пустая, на стр. 73 двум исполнениям
  (504-01 и 504-02) напечатано одно и то же фото — позиции импортируются
  без фото/с общим фото, заглушки не выдумываются;
- у плафонов вместо рабочей температуры указаны цветовая температура и световой
  поток — пишутся в `specs.color_temperature` и `specs.luminous_flux`;
- в разъёмах и прочих устройствах название стоит в чёрной плашке (кегль ≈14 pt,
  на странице их несколько), а в таблице — только артикул с описанием; артикул
  бывает заводским (`97461Н-3716021-01`) и с пробелом (`ЗИСС 02.3713.000-10`);
  на стр. 77 в таблице напечатан артикул соседней позиции — `ARTICLE_OVERRIDES`;
  названия, которые не собираются из плашки и пометки, зафиксированы в
  `NAME_OVERRIDES`;
- на стр. 62 в таблице напечатан артикул предыдущей позиции (`А.3716.003`),
  хотя страница о `А.3716.004`; `ROW_BASE_OVERRIDE` переносит коды на артикул
  из заголовка.

## Материалы поставщика: фото и описания

После каталога позиции дозаполняются материалами из публичной папки на
Яндекс.Диске (7 разделов, 666 файлов). Файлы кладутся в `files/` (снимки) и
`docs/` (паспорта), их разбирают два скрипта:

```bash
pip install --break-system-packages pillow pillow-heif python-docx

# снимки: HEIC → JPEG (1600 px, без EXIF), галереи, обложка — лицевая сторона
python3 scripts/catalog/import_photos.py            # --dry-run для проверки

# описания: .docx / .txt / .ini → description и specs
python3 scripts/catalog/import_descriptions.py <папка с документами> --report --dry-run
```

`import_photos.py` привязывает снимок по артикулу из имени файла или папки,
сортирует ракурсы («один», «два», «три»), уводит в конец галереи скан страницы
каталога и чертежи, обложку берёт только из настоящих фото.

`import_descriptions.py` разбирает паспорт на название, особенности, функции,
параметры и комплектацию. В описание позиции дописывается только то, чего в
нём ещё нет — блок «Особенности», источник света, климатическое исполнение,
степень защиты, комплектация; характеристики дозаполняют `specs`. Расхождения
с каталогом не перезаписываются (каталог главнее), а печатаются в отчёт
вместе с файлами, для которых не нашлось позиции. Артикулы поставщика
сводятся к каталогу таблицей `ARTICLE_ALIASES` и нормализацией номера
исполнения: `А.3731.018-01` → `А.3731.018-21`, `А.3731.027-2` → `А.3731.027-02`.
