# CRM «Атланта»

[![CI](https://github.com/alexeychekalin/Atlanta-CRM/actions/workflows/ci.yml/badge.svg)](https://github.com/alexeychekalin/Atlanta-CRM/actions/workflows/ci.yml)
[![Node.js](https://img.shields.io/badge/Node.js-20%2B-3c873a)](https://nodejs.org)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-16%2F17-336791)](https://www.postgresql.org)
[![Vanilla JS](https://img.shields.io/badge/frontend-vanilla%20JS-f7df1e)](client/js)

CRM для производственно-торговой компании: **клиент → чертёж и состав (BOM) → расчёт → КП → заказ → отчёт**. Система ведёт базу клиентов с уровнями цен, каталог компонентов с модификациями и документами, чертежи с согласованием и журналом расчётов, заказы и коммерческие предложения, а также отчётность с выгрузкой в Excel/PDF.

Права проверяются на сервере по матрице ролей из БД, деньги считает только сервер, пользовательские данные экранируются на клиенте, загруженные файлы проходят проверку путей и сигнатур.

> Подробный аудит проекта, реестр найденных проблем и статус исправлений — в [`docs/ANALYSIS.md`](docs/ANALYSIS.md). Развёртывание на VPS — в [`DEPLOY.md`](DEPLOY.md).

## Возможности

### Продажи и клиенты

- **Аналитический дашборд** — KPI (выручка, маржинальность, комиссия агента), графики динамики заказов, дашборд руководителя, топ клиентов.
- **Заказы** — спецификации с наценками, комиссия принципала, статусы, оплата и отгрузка, вложения (счёт), экспорт Excel/PDF.
- **Коммерческие предложения** — позиции из каталога и чертежей, наценки уровней, сроки действия, PDF с корректной кириллицей, перевод в заказ.
- **Клиенты** — карточка с 9 вкладками: заказы, КП, счета, контакты, чертежи, согласования, расчёты, таймлайн, документы. Сайт клиента выводится ссылкой в шапке, блок реквизитов сворачивается (состояние запоминается), у администратора справа появляется вкладка «📁 Файлы».
- **Уровни ценообразования** — настраиваемые наценки (Розница, Опт, Крупный опт, Производство), назначаются клиенту и применяются автоматически.
- **Журнал расчётов** — снимок каждого расчёта: чертёж, клиент, принципал, состав, наценки, итог и автор.

### Чертежи, BOM и расчёты

- **Единая модель чертежей** — один BOM можно привязать к нескольким клиентам; у каждого клиента своя цена: фиксированная сумма или расчёт по его уровню цен с ручной наценкой связи.
- **Обязательный клиент-владелец** — чертёж без клиента не создаётся (проверяется и в UI, и в API).
- **Калькулятор** — расчёт спецификации по компонентам/модификациям, наценки по позициям (%, ₽), общие наценки, сохранение шаблона, «Сохранить как заказ».
- **Согласование отдельно от расчёта** — итерации и версии файла, комментарии, статусы; в каталог чертежей попадает только утверждённая версия.
- **Архив вместо удаления** — чертежи хранятся всегда, `DELETE` переводит в архив, `POST /:id/restore` возвращает.
- **Дедупликация по SHA-256** — повторная загрузка того же файла не создаёт копию, а предлагает привязать существующий чертёж.
- **Название из имени файла** и комментарий при загрузке — отдельного поля «название» нет; позже название можно поправить кнопкой ✏️ (состав, владелец и цены не меняются).

### Каталог и производство

- **Компоненты** — фото, артикулы, цены, категории, модификации с собственными фото и ценой, два режима отображения (витрина/таблица).
- **Документы компонентов** — сертификаты и информационные материалы (PDF/JPEG/PNG), массовая выгрузка ZIP (в том числе из заказа и калькулятора).
- **Производители и оборудование** — справочник производителей с реквизитами, номенклатура оборудования с типами и привязкой к чертежам.
- **Глобальный поиск** — по клиентам, заказам, КП, компонентам, чертежам и производителям.

### Аналитика и администрирование

- **Отчёты** — срезы по заказам, клиентам и принципалам, графики, экспорт Excel и PDF.
- **RBAC** — 10 разделов × действия (просмотр / изменение / удаление / экспорт), матрица редактируется в интерфейсе, права читаются из БД (кэш 30 секунд).
- **Пользователи и сессии** — JWT в httpOnly-cookie, TTL 12 часов, отзыв сессий при смене пароля, лимит попыток входа.
- **Настройки НДС** — ставка и режим отображения хранятся в БД, НДС фиксируется в заказах и КП.
- **Файлы администратора** — вкладка «📁 Файлы» в карточке клиента: загрузка документов, таблиц, изображений, архивов и чертежей (до 50 МБ) в отдельное хранилище, доступное только роли `admin`; переименование и удаление вместе с файлом.
- **Темы и PWA** — тёмная/светлая тема, манифест, service worker без кэширования API.

## Модель ценообразования

### Формула

Цены в системе хранятся **без НДС**. НДС начисляется сверху и фиксируется в документе на момент сохранения.

```
base_i      = цена × количество            // цена модификации, если она задана
subtotal    = Σ (base_i + base_i × item_markup% / 100 + item_markup₽)
levelAmt    = subtotal × level%
afterLevel  = subtotal + levelAmt
total       = afterLevel × (1 + global%) + global₽
```

- `item_markup%` / `item_markup₽` — наценка позиции BOM (`drawing_components`).
- `level%` — наценка уровня: ручная наценка связи → уровень цен клиента → снимок уровня в чертеже.
- `global%` / `global₽` — общая наценка расчёта (поля калькулятора, сохраняются в чертеже).

Фиксированная цена отменяет все наценки: итог равен фиксу.

### Цена чертежа для клиента

Один BOM может быть привязан к нескольким клиентам через `drawing_clients`. Приоритет источников цены:

1. `drawing_clients.fixed_price` — фикс-цена конкретного клиента;
2. `drawings.fixed_price` — устаревшая общая фикс-цена (только чтение старых данных);
3. `drawing_clients.markup_pct` — ручная наценка связи поверх BOM;
4. `client_pricing_levels.markup_pct` — уровень цен клиента;
5. `drawings.level_markup_pct` — снимок уровня на момент сохранения;
6. иначе — 0 %, цена равна сумме по составу.

Формула живёт в одном месте — [`server/src/services/drawings.js`](server/src/services/drawings.js) (`priceForClient`, `calculateDrawingPrice`), SQL-фрагменты сумм — в [`server/src/services/drawings-sql.js`](server/src/services/drawings-sql.js). Клиент не пересчитывает деньги «своей» формулой: он показывает то, что вернул сервер.

Где считается цена:

| Экран / документ | Эндпоинт | Что отдаёт |
|---|---|---|
| Список чертежей | `GET /api/drawings` | `client_prices[]` по каждой связи, `total_cost` для выбранного клиента или владельца |
| Карточка чертежа | `GET /api/drawings/:id` | `clients[]` с ценой каждой связи, `price` — цена владельца |
| Цена для клиента | `GET /api/drawings/:id/price?client_id=` | итог, наценки и признак фикс-цены |
| Журнал расчётов | `POST /api/drawings/calculations` | сервер пересчитывает состав и сохраняет снимок |
| Документы клиента | `GET /api/clients/:id/documents/drawings`, `.../calculations` | `total_cost` и `client_fixed_price` по связи клиента |

### НДС

- Ставка и включённость хранятся в `system_settings` (`GET/PUT /api/settings/vat`), по умолчанию 22 %.
- `vat_amount = subtotal × rate / 100`, `total_with_vat = subtotal + vat_amount`; в заказах и КП сохраняются `vat_rate` и `vat_amount` — смена ставки не переписывает историю.
- Переключатель отображения меняет только показ сумм в интерфейсе.

## Роли и доступ

Права описаны матрицей по 10 разделам: дашборд, заказы, КП, клиенты, калькулятор, чертежи, компоненты, оборудование, отчёты, настройки. Матрица редактируется в **Настройки → Роли**, изменения действуют без перелогина (кэш прав — 30 секунд).

| Роль | Код | Назначение |
|---|---|---|
| Администратор | `admin` | Полный доступ, пользователи, роли, настройки НДС |
| Менеджер по продажам | `manager` | Заказы, КП, клиенты, калькулятор, отчёты; без удаления и настроек |
| Инженер-конструктор | `technologist` | Чертежи, калькулятор, компоненты, оборудование |
| Наблюдатель | `viewer` | Только просмотр разрешённых разделов |
| Неавторизованный | `guest` | Гостевой доступ; по умолчанию все разделы выключены |

Сервер проверяет права по матрице из БД (`requirePermission(section, action)` + `hasPermission` в маршрутах, кэш 30 секунд), интерфейс лишь скрывает недоступные кнопки. Сессия — JWT в httpOnly-cookie; смена пароля увеличивает `token_version` и отзывает старые токены.

## Быстрый старт

### Вариант 1. Docker Compose

```bash
git clone https://github.com/alexeychekalin/Atlanta-CRM.git
cd Atlanta-CRM

# Обязательные секреты — без них compose не запустится
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" >> .env
echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env

docker-compose up -d --build

# Первичная инициализация: миграции, роли, базовые пользователи
docker-compose exec app sh -c "cd server && npm run db:init"
```

Откройте `http://localhost:3000`. Проверка живости — `GET /api/health`.

### Вариант 2. Локально (Node.js + PostgreSQL)

```bash
# 1. Зависимости (корневой postinstall поставит их и в server/)
npm install

# 2. Конфигурация
cp server/.env.example server/.env
# Укажите DATABASE_URL и JWT_SECRET — без JWT_SECRET сервер не стартует

# 3. Схема, миграции, роли, пользователи
npm run db:init

# 4. Запуск
npm run dev       # node --watch, режим разработки
npm start         # прод-запуск без --watch
```

Откройте `http://localhost:3000`.

### Вариант 3. Демо без PostgreSQL (PGlite)

Подходит, чтобы посмотреть систему без установки СУБД: PostgreSQL собирается в WASM, данные лежат в `.pglite` в корне проекта (каталог в `.gitignore`).

```bash
cd server
npm install
npm run demo:init   # схема + миграции + роли + демо-данные
npm run demo        # http://localhost:3000
```

`demo:init` **пересоздаёт** демо-базу. Демо-набор: 6 клиентов, 12 компонентов, 5 чертежей, 12 заказов, 3 КП, 5 ролей.

Каталог данных можно переопределить: `PGLITE_DIR=/path/to/data npm run demo`.

## Конфигурация

Переменные окружения сервера (`server/.env`, в Docker — `environment` в compose):

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `DATABASE_URL` | да | — | Строка подключения к PostgreSQL |
| `JWT_SECRET` | да | — | Подпись токенов; без неё сервер не стартует |
| `PORT` | нет | `3000` | Порт HTTP-сервера |
| `NODE_ENV` | нет | `development` | Метка режима в логе запуска; скрипт `npm start` в `server/` выставляет `production` |
| `COOKIE_SECURE` | нет | `false` | `true` — cookie только по HTTPS (после настройки SSL) |
| `TRUST_PROXY` | нет | `false` | Доверять `X-Forwarded-*` от nginx |
| `CORS_ORIGINS` | нет | — | Дополнительные разрешённые Origin через запятую |
| `PGLITE_DIR` | нет | `.pglite` в корне проекта | Каталог демо-базы (только dev) |

Секреты не хранятся в репозитории: `.env` в `.gitignore`, `docker-compose.yml` требует `POSTGRES_PASSWORD` и `JWT_SECRET` из окружения.

### Схема данных (основное)

```
clients ── client_pricing_levels          уровень цен клиента
clients ──* drawings                      клиент-владелец (обязателен при создании)
drawings ──* drawing_components ── components
drawings ──* drawing_clients              связи с клиентами: наценка и фикс-цена
drawings ──1 drawing_approvals ──* drawing_approval_versions / comments
drawings ──* drawing_calculations         журнал расчётов (снимки)
clients ──* client_files                   файлы администратора (видит только admin)
orders ──* order_items                    заказы и позиции
proposals ──* proposal_items              КП и позиции
manufacturers ──* manufacturer_products ──* manufacturer_product_components
roles ──* users
system_settings                          настройки НДС
```

Всего в `schema.sql` — 32 таблицы. Ключевые инварианты:

- `drawings.client_id` — владелец; API не создаёт чертёж без клиента и не меняет владельца через `PUT`;
- цена и фикс-сумма живут на связи `drawing_clients`, а не на чертеже;
- чертежи не удаляются — только `archived_at`;
- один файл — один чертёж (`drawings.file_hash`, SHA-256);
- одна утверждённая версия согласования — один чертёж (`drawings.approval_id` уникален).

## База данных и миграции

Схема и миграции применяются одной командой; реестр `schema_migrations` определяет, что уже применено, поэтому повторный запуск безопасен:

```bash
cd server
npm run db:init       # схема + миграции + роли + пользователи (первый запуск)
npm run db:migrate    # только новые миграции
npm run db:schema     # schema.sql через psql (чистая установка вручную)
```

Как работает `db:migrate`:

1. Создаёт `schema_migrations`, если её нет.
2. Читает `src/db/migration_*.sql` в алфавитном порядке.
3. Применяет только новые файлы, каждый — в своей транзакции.
4. Записывает имя файла в реестр.

Правила для новой миграции:

- файл `src/db/migration_<тема>.sql`, идемпотентный (`IF NOT EXISTS`, `ON CONFLICT`);
- проверяйте на копии боевой базы (для демо: `cp -r .pglite /tmp/pglite-copy`, затем `PGLITE_DIR=/tmp/pglite-copy npm run demo:migrate`);
- актуальную схему для чистой установки дублируйте в `schema.sql`.

Демо-режим применяет те же миграции: `npm run demo:migrate`.

## API

Базовый префикс — `/api`, авторизация — cookie `atlanta_token` (или `Authorization: Bearer`). Ошибки — JSON `{ "error": "…" }`; 401 — нет/истекла сессия, 403 — нет права, 404 — объект не найден, 409 — конфликт (например, дубликат файла).

| Модуль | Эндпоинт | Описание |
|---|---|---|
| Здоровье | `/api/health` | Проверка живости (Docker healthcheck) |
| Авторизация | `/api/auth` | `login`, `logout`, `me`, права гостя |
| Клиенты | `/api/clients` | CRUD, поиск, фильтры, `?limit=`, сайт клиента |

### Клиентские тесты

Страницы `client/js/pages/*.js` проверяются в `vm`-песочнице с минимальными заглушками (`Table`, `API`, `Modal`, `Toast`). Это позволяет ловить регрессии разметки и логики без браузера и сборщика:

- после загрузки `components/escape.js` helpers нужно явно положить в песочницу (`sandbox.esc = sandbox.window.esc`);
- для inline-обработчиков проверяется, что в них попадают только идентификаторы;
- расчёты сверяются с `services/drawings.js`, а не с копией формулы.

## Разработка

### Правила

- **Деньги считает сервер.** Клиент отображает ответ API; формулы нельзя дублировать в браузере — для чертежей используйте `GET /api/drawings/:id/price` или поле `price` в карточке.
- **Права — на сервере.** Новый маршрут монтируется с `requirePermission(section)` (или `requireAuth`), запись дополнительно проверяет действие в `hasPermission`.
- **Пользовательские данные экранируются.** В HTML — `esc()`, в URL — `safeUrl()`; в inline-`onclick` передаются только идентификаторы, а имена и тексты берутся из состояния страницы.
- **Чертежи не удаляются.** Только архив (`archived_at`) и восстановление.
- **Файлы — только внутри `/uploads`.** Пути нормализуются, сигнатуры проверяются, SVG запрещён.
- **Миграции идемпотентны** и регистрируются в `schema_migrations`; схема для чистой установки — в `schema.sql`.
- **Справочники не задваиваются.** Статусы клиентов, категории компонентов и типы техники вставляются через `WHERE NOT EXISTS`, а `migration_dedupe_dictionaries.sql` чистит дубли и держит уникальные индексы по названию — повторный деплой не плодит значения в настройках.

### Как добавить страницу

1. Создайте `client/js/pages/<page>.js` с объектом `XxxPage` (`render`, обработчики).
2. Подключите скрипт в `client/index.html`.
3. Добавьте страницу в список `pages` в `client/js/app.js` и в навигацию.
4. Проверьте права через `API.can('section', 'view')` и добавьте раздел в матрицу ролей.

### Как добавить эндпоинт

1. Создайте/дополните файл в `server/src/routes/`.
2. Смонтируйте его в `server/src/index.js` с проверкой прав.
3. Валидируйте входные данные (числа, идентификаторы, FK) и возвращайте понятные ошибки 400/404/409.
4. Добавьте тест в `server/test/`.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| Сервер не стартует: «JWT_SECRET не задан» | Добавьте `JWT_SECRET` в `server/.env` или окружение |
| 401 после смены пароля | Так задумано: `token_version` отзывает старые сессии — войдите заново |
| 403 при работе менеджера | В матрице ролей у раздела нет нужного действия: **Настройки → Роли** |
| Демо-база «сломалась» после экспериментов | `rm -rf .pglite && cd server && npm run demo:init` |
| Порт 3000 занят | `PORT=3001 npm run demo` (или `npm start`) |
| Файлы не открываются | Проверьте, что путь начинается с `/uploads/` и файл существует в `server/uploads/` |
| Cookie не ставится за HTTPS | Установите `COOKIE_SECURE=true`; за HTTP оставьте `false` |
| Линтер ругается на клиентский JS | Запускайте из `server/`: `npm run lint` |
| После деплоя в настройках задвоились статусы/категории/типы техники | Примените миграции: `cd server && npm run db:migrate` — `migration_dedupe_dictionaries.sql` почистит дубли и поставит уникальные индексы |

## Статус и план

Работа идёт в ветке **`arena/65030bab-atlanta-crm`** ([PR #1](https://github.com/alexeychekalin/Atlanta-CRM/pull/1)); в `main` изменения пока не влиты — эта ветка считается рабочей.

Закрыто в ветке:

- **P0–P1 аудита** — RBAC на сервере, защита загрузок и секретов, серверный расчёт цен и НДС, фиксация НДС в документах, миграции с реестром, тесты и CI.
- **Модель чертежей** — общий BOM на нескольких клиентов, фикс-цена и наценка на связи, архив вместо удаления, дедупликация по SHA-256, отдельные согласования, журнал расчётов.
- **Клиентский контекст и валидация** — обязательный клиент-владелец, цена по связи клиента в калькуляторе и документах, безопасные inline-обработчики, клиенты без обрезки на 50, единая серверная формула цены.
- **Доработки по итогам наполнения** — сворачиваемые реквизиты, сайт клиента, переименование чертежей, админская вкладка «Файлы» в карточке клиента, идемпотентные справочники при деплое.

Открыто (P2–P3, см. `docs/ANALYSIS.md` §9.5): нумерация документов через последовательности, аудит и логирование, лимиты тела запроса, бэкапы, экспорт журнала расчётов, UX-доработки.
