# CRM «Атланта»

Современная CRM-система для производственных и торговых компаний. Включает управление клиентами, заказами, коммерческими предложениями, каталогом компонентов (BOM) с модификациями и документами, базой чертежей, калькулятор спецификаций, каталог оборудования производителей, уровни ценообразования, отчётность с экспортом в Excel/PDF и гибкую ролевую модель доступа (RBAC).

---

## 🚀 Возможности системы

### Основные модули

* **📊 Аналитический дашборд** — ключевые KPI (выручка, маржинальность, комиссия агента), графики динамики заказов (столбчатые и кольцевые), дашборд руководителя, топ клиентов.
* **📦 Управление заказами** — расчёт комиссий принципала, спецификации позиций с наценками (поуровневые + ручные), степперы ±, добавление из каталога компонентов и чертежей, экспорт и статусы.
* **📝 Коммерческие предложения (КП)** — формирование КП для клиентов с позициями из каталога, наценки уровней, статусы, сроки действия, экспорт.
* **👥 База клиентов** — карточка клиента с таймлайном событий (звонки, встречи, оплаты), загрузка документов, история чертежей, контакты, пользовательские статусы, присвоение уровня ценообразования.
* **🧮 Калькулятор чертежей** — расчёт спецификаций компонентов (BOM) с наценками (%, ₽), сохранение в базу чертежей, перевод в заказ, скачивание сертификатов и документов компонентов (ZIP).
* **📐 Каталог чертежей** — единая база: один BOM можно привязать к нескольким клиентам, и у каждого клиента своя цена — фиксированная сумма или расчёт по BOM с уровнем цен клиента и ручной наценкой связи. Название чертежа берётся из имени загруженного файла, к загрузке добавляется комментарий. Чертежи не удаляются, а уходят в архив; повторная загрузка того же файла распознаётся по SHA-256. Согласование — отдельный процесс: в чертежи попадает только утверждённый файл.
* **🧾 Журнал расчётов** — снимок каждого расчёта: чертёж, клиент, принципал, состав, наценки, итог и автор.
* **🔩 Каталог компонентов** — фото, артикулы, цены, категории, модификации с фото, два режима отображения (витрина / таблица), прикрепление сертификатов и информационных документов (PDF/JPEG/PNG).
* **🏭 Каталог производителей и оборудования** — база производителей с контактами и реквизитами, номенклатура оборудования с типами, привязкой к чертежам и ценообразованием.
* **💰 Уровни ценообразования** — настраиваемые уровни наценок (Дилер, Розница и т.д.) с привязкой к клиентам, автоматическое применение наценки при формировании заказов и КП.
* **📈 Отчёты и аналитика** — срезы по заказам, клиентам, принципалам, выгрузка в Excel (`.xlsx`) и PDF с корректной кириллицей.

### Системные функции

* **🛡️ RBAC** — ролевая модель с интерактивной матрицей прав по 8 разделам (просмотр / редактирование / удаление / экспорт), права проверяются на сервере и читаются из БД при каждом запросе.
* **🍪 Безопасные сессии** — JWT в httpOnly-cookie, ограничение попыток входа, отзыв сессий при смене пароля.
* **🔐 Защита загрузок** — файлы принимаются только из `/uploads`, проверяются по магическим байтам, SVG запрещён, выдача — только авторизованным.
* **👤 Управление пользователями** — создание, редактирование, назначение ролей с гранулярными правами.
* **💲 Настройка НДС** — цены в системе хранятся без НДС; рядом показывается сумма с НДС (настраиваемая ставка и переключатель отображения). НДС начисляется сверху и фиксируется в заказах и КП.
* **📎 Документы компонентов** — загрузка сертификатов и информационных сообщений (PDF/JPG/PNG), скачивание ZIP-архивом из заказов и калькулятора.
* **🌓 Тёмная / светлая тема** — переключение с сохранением в localStorage.

## 📦 Быстрый старт

### Вариант 1: Docker Compose (рекомендуется)

```bash
git clone https://github.com/alexeychekalin/AtlantaCRM-deploy.git
cd AtlantaCRM-deploy

# Обязательно задайте секреты — без них compose не запустится
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" >> .env
echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env

docker-compose up -d --build

# Первичная инициализация: схема, миграции, роли, администратор
docker-compose exec app sh -c "cd server && npm run db:init"
```

Откройте: `http://localhost:3000`

### Вариант 2: Локальный запуск (Node.js + PostgreSQL)

```bash
# 1. Установить зависимости
npm run postinstall

# 2. Настроить подключение к БД
cp server/.env.example server/.env
# Отредактируйте DATABASE_URL и JWT_SECRET в server/.env
# (JWT_SECRET обязателен, без него сервер не стартует)

# 3. Применить схему БД, миграции и создать роли
npm run db:init

# 4. Запустить
npm run dev       # режим разработки (node --watch)
npm start         # продакшн
```

Откройте: `http://localhost:3000`

### Вариант 3: демо без PostgreSQL (PGlite)

Для проверки на локальной машине без установленного PostgreSQL — встроенная WASM-версия базы:

```bash
cd server
npm install
npm run demo:init   # схема + миграции + роли + демо-данные
npm run demo        # http://localhost:3000
```

База хранится в `.pglite` в корне проекта и не попадает в git. Демо-данные включают клиентов, заказы, чертежи, КП и три учётные записи.

## 🗄️ Миграции БД

Схема и миграции применяются одной командой — реестр `schema_migrations` сам определяет, что уже применено, и повторный запуск ничего не дублирует:

```bash
cd server
npm run db:migrate          # применить новые миграции
npm run db:init             # схема + миграции + роли (первый запуск)
```

Что делает `db:migrate`:

1. Создаёт таблицу `schema_migrations`, если её нет.
2. Читает все `src/db/migration_*.sql` в алфавитном порядке.
3. Применяет только новые файлы, каждый — в отдельной транзакции (`BEGIN … COMMIT`).
4. Записывает имя файла в реестр.

Добавление новой миграции: положите файл `src/db/migration_<тема>.sql` с идемпотентными конструкциями (`IF NOT EXISTS`) — он применится при следующем деплое (`deploy.sh`, `update.sh`) или вручную. `schema.sql` содержит актуальную схему для чистой установки.
